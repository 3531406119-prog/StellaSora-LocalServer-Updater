# 工具二：活动任务进度修复（ActivityTask 补丁）

> 适用症状：**活动关卡打通了，但活动任务永远显示未完成**；顺带解决"灾变防线打完看不到痕迹"的显示部分。

## 为什么会出现这个问题（原因在服务端，不在客户端）

本地服（Nebula）目前对两块功能**只建了框架、没实现逻辑**：

| 缺的东西 | 后果 |
|---|---|
| 活动任务从不累计进度（`TaskActivity` 的 `curProgress` 一直是 0） | 任务永远显示 0/xxx，打多少关都不涨 |
| 没有 `ActivityTaskRewardReceive` 请求处理器 | 即使显示完成，"领取"按钮也没有服务端逻辑 |
| 没有 Vampire（灾变防线）排行处理器 | 关卡记录其实有写库，但赛季排行/积分面板是空的 |

这不是官服限制，就是模拟器还没做到这块。上游更新很勤（2026-10 还在持续加功能），等作者实现是最彻底的；本工具是**临时补丁**：把进度补满让你看得见，并用 GM 邮件把任务奖励直接发给你。

## 它具体做什么

1. 连到本地服的 MongoDB，读你这条玩家的 `activity` 记录；
2. 把所有 `TaskActivity` 里任务的 `curProgress` 直接补成 `maxProgress`（游戏里显示"已完成"）；
3. 按 `Server\Resources\bin\ActivityTask.json` 里的 `Tid1/Qty1`、`Tid2/Qty2` 算出这些任务本该给的奖励；
4. 用 GM 接口 `POST /api/command` 发一封补偿邮件给你（需要你在游戏里**已登录**，否则会提示 `Targeted player not found or offline`，可以先不发邮件、只补进度）。

## 用法

```bat
:: 默认：补进度 + 发补偿邮件
run.cmd "D:\Stella Sora" 10003

:: 只检查，不改数据库
run.cmd "D:\Stella Sora" 10003 dry
```

- 第一个参数：本地服包根目录（里面是 `Server\`）
- 第二个参数：你的玩家 UID（服务端日志登录成功那几行里有，或 GM 工具里显示；常见是 `10003`）
- 如果双击运行，按提示把这两个值粘进去即可。

**建议流程**：退出游戏（让服务端把玩家数据落盘）→ 跑工具 → 重新启动游戏登录 → 打开活动页看任务是否显示已完成、邮箱是否有补偿邮件。

> 工具不会启动/停止服务端；它只连 MongoDB 改一条玩家记录 + 调一次 GM 接口。

## 需要什么

- 本地服自带的 Java 21（`Server\Runtime\Java\bin\java.exe`，脚本会自动用它）
- 服务端的 `Server\lib\Nebula.jar`（里面有 MongoDB 驱动，工具拿它当依赖）
- 如果你把整合包挪了位置，`run.cmd` 的第一个参数改成新路径即可

## 回滚

工具只改 `activity` 集合里**你这条玩家**的记录，且只动 `TaskActivity` 任务的 `curProgress`：

- 运行前先复制一份 `存档\Database`（整份目录）或压缩成 zip，改坏了直接还原；
- 想撤销补丁：把备份里的 `存档\Database` 覆盖回去，或者把任务的 `curProgress` 改回 0 即可。

## 局限（务必知道）

- 这是**补显示 + 补奖励**，不是把功能实现了：任务"领取"按钮依旧点不动（服务端没有对应处理器），所以我们用邮件发奖励代替；
- 活动任务数据每天/每期可能会被服务端重置，重置后要再跑一次；
- 上游一旦实现了活动任务逻辑，请不要再跑这个工具（以免和真实进度冲突）。
